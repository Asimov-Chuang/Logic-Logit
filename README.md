# Logic-Logit

**A Logic-Based Approach to Choice Modeling**  
Shuhan Zhang, Wendi Ren, Shuang Li · **ICLR 2025**

[Paper](https://openreview.net/forum?id=vJgJSrYPe1) ·
[Interactive tutorial](Gentle-Introduction-to-Logic-Logit.ipynb)

A teaching implementation of Logic-Logit, adapted from the authors' introductory
notebook. It demonstrates binary predicate construction, conjunction-rule search,
conditional-gradient-style mixture learning, held-out choice prediction, and
inspection of learned rules.

The default example runs on **synthetic hotel-choice data**, with no external
download or Google Drive dependency. It is a runnable introduction, **not a full
reproduction package for the paper's experiments**.

## Quick start

Use Python 3.11 or 3.12:

```bash
git clone https://github.com/Asimov-Chuang/Logic-Logit.git
cd Logic-Logit
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python demo.py
```

Or open `Gentle-Introduction-to-Logic-Logit.ipynb` in your notebook editor,
select the same environment as its kernel, and run all cells in order from a
fresh kernel. Keep the working directory at the repository root.

The demo uses 150 training and 50 test sessions, seed 7, one CPU thread, an initial
logit component, and two candidate-component additions. Settings intentionally
use smaller optimization budgets than the original notebook. The notebook shows
the training curve, held-out NLL, and interpretable rule coefficients.

## How it works

1. **Predicates:** fixed bins and training-fitted quantiles convert raw features
   into binary predicates. The test set uses the same ordered columns.
2. **Taste components:** masked logit probabilities depend on weighted rule
   features. Each rule is a conjunction (AND) of predicates.
3. **Rule search:** the support-fitting procedure selects product predicates and
   expands them with product/customer conjunctions using gradient-based scores.
4. **Mixture learning:** an outer conditional-gradient-style loop adds candidate
   preference types and refits their mixing weights.

The support subproblem uses the original tutorial's **heuristic Adam solver**;
it is not an exact linear minimization oracle. This release does not assert a
formal convergence guarantee for that heuristic. If approximate mixture fitting
would worsen the current training NLL, the previous mixture is retained and the
new component receives zero weight. Rule pruning is not implemented here.

## Changes from the original introductory notebook

- Replaced personal Google Drive paths with a synthetic default and documented
  relative paths for locally supplied data. No real Expedia data are redistributed.
- Fit quantile boundaries only on training data and reuse identical bin labels
  and feature ordering for all splits. Fixed-bin predicates are allocated even
  when a category does not occur in the training sample.
- Preserved the original nested support search and mixture-training structure,
  while extracting it into an importable module.
- Removed the unused `opt='lbfgs'` option and dormant optimizer/pruning snippets;
  the tutorial uses Adam explicitly.
- Replaced full padded `log(0)` loss differentiation with the chosen-alternative
  NLL and its analytic probability gradient; validated it against autograd.
- Corrected initial-component rule bookkeeping for prediction, generalized
  offer-set padding, and fixed higher-order conjunction generation.
- Added held-out prediction and a check that predictions match training caches.
- Removed manually entered comparison curves. Every displayed score/plot is
  generated by the current synthetic run.

These changes improve the teaching implementation's portability and consistency.
They do not establish reproduction of the original paper's numerical results.

## Validation

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python verify_notebook.py
```

The checks cover identical train/test feature semantics, unseen categories,
constant quantile columns, invalid labels, variable-size masked choice sets,
probability normalization, agreement between cached and independently recomputed
predictions, NLL gradients, and higher-order rule features. Notebook execution
writes a fresh copy to `results/executed-tutorial.ipynb`.

## Real data

## Verified example run

Validated on Python 3.12.14, PyTorch 2.14.1, NumPy 2.5.3, and pandas 2.3.3.
All 7 tests passed, and all 8 notebook code cells executed from a fresh kernel.
With the default synthetic seed and settings, test NLL was 1.239 versus 1.487
for uniform choice. These are example-run measurements, not paper results or
performance guarantees.
